# GradeFlow AI

Report cards (SF9) and permanent records (SF10) for Senior High School (Grades 11–12).
The teacher uploads the spreadsheet they already have. AI reads it, and the teacher previews the SF9 and SF10 for any learner (picked by LRN) and downloads or prints the PDFs.

Built with **Next.js (App Router) + React + TypeScript**. The AI import runs in Next.js API routes, so there is one app and one command to run.

## Run it

```bash
npm install
cp .env.example .env     # then put your free AI key in .env
npm run dev              # http://localhost:3000
```

Production: `npm run build && npm start`.

Free AI keys (pick one provider in `.env`): Gemini https://aistudio.google.com/apikey, Groq https://console.groq.com/keys, OpenRouter https://openrouter.ai/keys. Ollama (https://ollama.com) needs no key and runs on your own computer.

## How the AI import works

1. **SF9** (`POST /api/import`): the server sends only the top ~15 rows and the list of target fields to the AI, which answers with a column mapping (JSON). **Code, not the model, copies every value** from the sheet. No grade is generated by AI; blank stays blank. If the AI is unavailable, the built-in template reader is used.
2. **SF10** (`POST /api/import-sf10`): an SF10 is a form, so the AI reads the whole sheet (one learner per sheet) and returns the record. Every grade it returns is checked against the sheet's own cells; a value that is not in the sheet is dropped.

## Keeping the key and the bill safe

- The key lives only in `.env` (git-ignored) on the server. The browser never sees it and `/api/health` only says whether it is set.
- Never put the key in `.env.example` (that file is committed). Do not paste it in chat, issues or screenshots.
- Optional limits (all **off** by default, see `.env.example`): per-visitor rate limit, a daily cap on AI calls for the whole server, a max number of sheets per SF10 upload and a max sheet size. Over a limit the API answers 429/422 with a clear message and **no AI call is made**. Turn them on before sharing the server or when using a paid key.
- Set `APP_ACCESS_CODE` when anyone else can reach the server; the app asks for the code once per browser session.
- Free tiers may use submitted data to improve their models. Use **fictional data only** for demos; for real learner data use Ollama or a paid plan with data use disabled.

## Project layout

```
src/app/(app)/      pages: upload, verification, report-card, generated-reports, sf10, summary, history, settings, help
src/app/api/        import, import-sf10, health
src/components/     Shell, Providers (toast + modal), ReportCard (SF9), Sf10Sheet (SF10), Icon
src/lib/            curriculum, grading, store, actions, sf10Record, pdf/ (jsPDF drawing for SF9 and SF10)
src/server/         llm (free AI providers), mapper, sf10, template, extract, guard
tests/              vitest tests for the server code
samples/            fictional sample workbooks (messy, and the standard template) and the scripts that build them
public/reel/        27-second promo reel (plain HTML/CSS/JS) and its synthesized soundtrack
scripts/            capture-reel.mjs (films the real app for the reel), render-reel.mjs (turns the reel into an MP4)
```

## Promo reel

`public/reel/index.html` is a 34-second, 1920×1080 promo with six scenes: identity, promise, how to use, SF9 and SF10, no guessing, and the closing card. It uses only fictional learners.

- **The app scenes are real.** Scenes 3 to 5 show screenshots of the running app, not mockups: the Upload page, the progress indicator frame by frame, the LRN search one key at a time, the SF9 page, the download toast, the SF10 page, and a blank grade flagged "2 to check". They also show the SF9 and SF10 PDFs the app downloads, page for page. The cursor and camera are animated on top of the captures.
- **After a UI change, film it again:** run `npm run build`, then `npm run reel:capture`. `scripts/capture-reel.mjs` starts the built app with no AI key, uploads `samples/template_class.xlsx` (fictional learners, read by the built-in template reader, so no data leaves the machine), and writes the captures, element positions and PDF pages to `public/reel/shots/`. It needs Playwright, ffmpeg and `pdftoppm` (poppler-utils). `python3 samples/make_template_class.py` rebuilds the sample.
- The captures show what the app shows, including the school name and seal set in `src/lib/store.ts` and `public/assets/`.

- **Watch it:** run `npm run dev` and open http://localhost:3000/reel/index.html, or just open the file in a browser. Keys: Space play/pause, ← → seek, R restart, M sound, F fullscreen.
- **Options:** `?url=your-app.vercel.app` puts your address in the closing pill. `?once` plays it once instead of looping.
- **Music:** `public/reel/soundtrack.js` synthesizes an original score (no samples, no third-party music, nothing to license) from the reel's own timeline. Every cut gets a hit, and the UI moments get small sounds: file drop, check pings, key clicks for the LRN search, the download click. The sound starts off because browsers block autoplay with sound, so press the speaker button or M. The track is built on first use, which takes about a second.
- **Export an MP4:** `npm run reel` writes `gradeflow-ai-reel.mp4` with the soundtrack (needs Playwright with Chromium and ffmpeg). Every frame is drawn at an exact time, so the video has no dropped frames. Other options:
  - `npm run reel -- out.mp4 --fps 60 --url your-app.vercel.app` changes the defaults.
  - `--music track.mp3` uses your own track instead. It loops if it is shorter than the reel and fades out at the end. Use only music you have the rights to.
  - `--no-music` makes a silent video.
  - `--wav soundtrack.wav` writes only the soundtrack.
  - `--still 12.5 frame.png` saves one frame.
